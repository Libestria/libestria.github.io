Configurer son identifiant NIP-05 Nostr sur son propre domaine

Associe ta clé publique Nostr à une adresse lisible en hébergeant toi-même le fichier de correspondance.

Introduction

NIP-05 associe une clé publique Nostr à une adresse lisible, comme alice@exemple.fr. Tu peux héberger toi-même cette correspondance sur un domaine que tu contrôles.

Prérequis : un profil Nostr, un domaine, et un hébergement HTTPS où tu peux publier un fichier JSON et régler les en-têtes HTTP.

À savoir : NIP-05 associe une clé à un domaine, mais ne certifie pas l’identité civile de son titulaire. Il n’est pas nécessaire pour utiliser Nostr.

1. Choisir l’adresse et récupérer ta clé publique

Choisis une adresse, par exemple alice@exemple.fr. La partie avant @ accepte les lettres minuscules a-z, les chiffres 0-9, le tiret -, le souligné _ et le point .. Le domaine doit correspondre exactement à l’hôte du fichier ; n’ajoute pas www sauf si l’adresse l’utilise.

Pour associer le domaine lui-même à ton profil, tu peux choisir _@exemple.fr ; certains clients l’affichent comme exemple.fr.

  1. Dans ton client Nostr, copie la clé publique de ton profil.
  2. Si elle commence par npub1, récupère son format hexadécimal avec l’option d’export du client ou un convertisseur, tel que NostrCheck (npub ↔ HEX — EN).
  3. Vérifie que la clé HEX contient 64 caractères hexadécimaux en minuscules.
Sécurité : utilise uniquement ta clé publique. Ne saisis jamais ta clé privée nsec1… dans un convertisseur ou dans le fichier.

2. Créer le fichier nostr.json

Crée nostr.json et remplace la valeur fictive ci-dessous par ta clé publique HEX :

{
  "names": {
    "alice": "CLE_PUBLIQUE_HEX_DE_64_CARACTERES"
  }
}

Pour _@exemple.fr, remplace "alice" par "_". Tu peux ajouter d’autres noms dans le même objet "names", chacun associé à une clé HEX ; plusieurs noms peuvent volontairement pointer vers la même clé. Utilise des virgules entre les entrées, sans virgule après la dernière, et retire toutes les valeurs fictives avant publication.

Tu peux aussi ajouter un objet facultatif "relays" pour indiquer les relais où rechercher un profil. Associe chaque clé publique à une ou plusieurs URL wss:// pour aider les clients à trouver le profil. Plusieurs profils peuvent partager un relais ; cette indication ne garantit pas la disponibilité des événements.

{
  "names": { "alice": "CLE_PUBLIQUE_HEX_DE_64_CARACTERES" },
  "relays": {
    "CLE_PUBLIQUE_HEX_DE_64_CARACTERES": ["wss://relay.exemple.net"]
  }
}

Les valeurs de cet exemple sont fictives. Si tu renseignes "relays", répète exactement la même clé HEX que dans "names".

3. Publier le fichier et autoriser son accès

  1. À la racine publique de exemple.fr, publie le fichier à l’adresse exacte /.well-known/nostr.json.
  2. Vérifie qu’il est accessible en HTTPS, sans authentification ni redirection, et servi comme JSON.
  3. Pour permettre sa lecture par les clients Nostr dans un navigateur, configure l’en-tête HTTP suivant :
Access-Control-Allow-Origin: *

Teste l’adresse https://exemple.fr/.well-known/nostr.json?name=alice dans un navigateur. Elle doit renvoyer le JSON, pas une page HTML ni une erreur 404. Certains hébergements bloquent les dossiers commençant par un point : vérifie que .well-known est bien publié.

4. Ajouter et vérifier l’identifiant

  1. Dans les réglages de ton profil Nostr, saisis alice@exemple.fr dans le champ « NIP-05 » ou équivalent, puis publie la modification. Les intitulés et la prise en charge varient selon le client.
  2. Vérifie que la clé de names.alice correspond exactement à la clé publique de ton profil.
  3. Contrôle la réponse et ses en-têtes avec :
curl -i 'https://exemple.fr/.well-known/nostr.json?name=alice'

La réponse attendue est 200 OK, sans redirection, avec un JSON valide et l’en-tête Access-Control-Allow-Origin: *. Le client doit ensuite reconnaître l’adresse, parfois après un délai de cache.

  • 404 : vérifie le chemin et la publication de .well-known.
  • JSON invalide : contrôle les guillemets doubles, les virgules et l’absence de commentaires.
  • Adresse non reconnue : vérifie le nom, la clé HEX en minuscules et le champ de profil.
  • Échec dans un client Web : vérifie CORS et l’absence de redirection.

Conclusion

Ton domaine peut maintenant associer une adresse NIP-05 à ta clé publique. Garde le fichier accessible en HTTPS et vérifie la correspondance après tout changement de clé, de domaine ou d’hébergement. Dans Nostr, ta clé publique reste la référence de ton profil.
